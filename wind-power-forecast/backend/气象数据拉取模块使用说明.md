# 气象数据拉取模块使用说明

## 前置条件

1. KingBase、Redis、Celery Worker 和 Celery Beat 已运行。
2. 当前账号拥有 `manage_weather_data` 权限。
3. Worker 可以访问目标气象服务器和持久化保存目录。
4. 已配置 `CREDENTIAL_ENCRYPTION_KEY` 或对应只读密钥文件。

## 创建连接

```http
POST /api/v1/weather-fetch/connections
Content-Type: application/json

{
  "name": "场站气象服务器",
  "farm_code": "zyx",
  "host": "192.168.1.100",
  "port": 22,
  "username": "weather",
  "auth_type": "password",
  "password": "由部署人员填写"
}
```

创建后调用以下接口验证连接：

```http
POST /api/v1/weather-fetch/connections/1/test
```

## 创建拉取任务

```http
POST /api/v1/weather-fetch/tasks
Content-Type: application/json

{
  "name": "每日气象文件拉取",
  "connection_id": 1,
  "farm_code": "zyx",
  "remote_path": "/data/weather",
  "path_pattern": "YYYY_MMDDHHNN",
  "time_strategy": "latest",
  "file_pattern": "*.dat",
  "schedule": "0 6 * * *",
  "save_path": "/data/weather/{date}",
  "processing_options": [],
  "deduplication_options": ["skip_existing"],
  "timeout": 300,
  "retry_count": 3
}
```

`schedule` 使用五段式 cron，字段依次为分钟、小时、日期、月份和星期。接口会拒绝字段数量或取值无效的表达式。

## 任务变更生效

任务配置写入数据库后，Celery Beat 会自动重新加载。默认最长等待 60 秒，本地开发脚本设置为 30 秒。无需重启 Web 服务。

常用接口：

```text
GET    /api/v1/weather-fetch/tasks
PUT    /api/v1/weather-fetch/tasks/<id>
DELETE /api/v1/weather-fetch/tasks/<id>
POST   /api/v1/weather-fetch/tasks/<id>/toggle
GET    /api/v1/weather-fetch/tasks/<id>/logs
GET    /api/v1/weather-fetch/scheduler/status
```

## 手动执行

```http
POST /api/v1/weather-fetch/tasks/1/run
```

成功提交时返回 HTTP 202：

```json
{
  "message": "任务已进入执行队列",
  "status": "queued",
  "celery_task_id": "任务编号"
}
```

提交成功只表示队列已经接收请求。执行结果以任务日志和 `last_run`、`status` 字段为准。同一任务正在运行时，新请求会被 Redis 锁安全跳过。

## 调度服务管理

`/api/v1/weather-fetch/scheduler/restart` 会返回 HTTP 409，因为 Celery Beat 由容器或 systemd 管理。生产环境使用以下命令检查和重启：

```bash
docker compose -f deploy/docker-compose.prod.yaml ps celery-beat celery-worker redis
docker compose -f deploy/docker-compose.prod.yaml restart celery-beat
```

## 故障排查

1. 返回 503 时检查 Redis 和 Celery Worker。
2. 计划任务未触发时检查 Celery Beat 日志和 cron 表达式。
3. SSH 失败时检查网络、账号、密钥路径和凭据解密配置。
4. 文件写入失败时检查 Worker 内的目录挂载和权限。
5. 数据未进入预测链路时检查统一接入处理器或 E 文本管道，气象拉取任务只记录文件级处理结果。
