# 商业化基础版本说明

## 本分支目标

`codex/commercialization-foundation` 将开发仿真、现场接入、预测、上报和运维统一到一套稳定契约。现有预测算法实现保持原样，改动集中在数据输入、版本治理、运行进程、可观测性、发布安全和验收测试。

## 日常开发入口

Windows 开发人员运行：

```bat
start-scada-dev.bat
```

该入口会启动独立仿真测试床、数据库与 Redis、本地后端、SCADA Manager、DQYC 影子适配器、NWP 业务处理器、Celery 和 Vue。DQYC 默认从真实样本回放，原始文件保持不变，模型输入固定为 508 个时刻，业务层保留收到的全部时效。启动失败会保留终端并输出具体阶段，便于定位 Docker、端口、迁移或依赖问题。

运行状态入口：

```text
前端菜单：运维与质量 → 运行控制中心
SCADA Manager：http://127.0.0.1:9102/ready
NWP 仿真控制：http://127.0.0.1:18084/state
NWP 影子目录：simulation/nwp-shadow/artifacts
后端健康：http://127.0.0.1:18080/health
```

## 数据库升级

新增迁移为：

```text
backend/migrations/versions/20260715_03_commercial_data_lineage.py
```

生产部署流程：

1. 备份数据库和当前发布配置。
2. 在生产副本执行 `alembic upgrade head`。
3. 核对 `ingestion_batches`、`source_observations`、`prediction_input_snapshots` 和模型治理字段。
4. 执行应用回归与查询性能抽样。
5. 在业务窗口升级正式数据库。
6. 保持 `DB_SCHEMA_STRICT=true`，结构不一致时停止启动。

## 配置启用顺序

1. 先完成场站主数据、数据库迁移和用户权限。
2. 配置 SCADA 点表、允许网段与 Worker 密钥，运行 FAT 后启用 SCADA。
3. 配置 NWP 分区目录和文件适配，确认每个启用场站有新鲜业务批次后启用 NWP。
4. 注册训练模型，核对数据集与制品摘要，由授权人员审批。
5. 配置下游上报端点，完成回执、重试和死信演练。
6. 执行离线发布校验和完整 FAT。
7. 进入至少七天的现场 SAT 连续运行观察。

## 仍需现场输入

以下内容依赖场站资料和真实内网，当前开发环境无法代替现场确认：

1. 正式 C104 点表，包含 CASDU、IOA、Type ID、时间标签、倍率、单位和质量位。
2. 场站时钟源、允许偏差、采样频率和断点续传规则。
3. 正式 NWP 更新周期和缺报规则。当前 DQYC 文件命名、字段、格点、时区和 508 时刻模型契约已由真实样本固化。
4. 电力分区网络地址、单向或双向传输约束、访问控制和密钥交付方式。
5. 下游服务器接口、鉴权、幂等键、回执、超时和限流要求。
6. 服务器 CPU、内存、磁盘、并发用户数、历史数据规模和备份窗口。
7. 准确率考核口径、预测出数时限、人工修正规则和模型审批责任人。
8. 极端天气实时数据源与事件保存要求。该功能当前继续标记为占位状态。

## 发布边界

本分支提供可进入联调和 FAT 的商业化基础版本。完成真实点表、真实 NWP、真实下游和连续运行 SAT 后，才具备场站正式投产条件。生产分支和当前生产容器不会因该分支的开发提交自动变化。
