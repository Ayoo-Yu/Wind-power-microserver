# 场站化系统架构

## 目标形态

系统采用一套产品代码和多种部署配置。开发环境使用本机前后端进程与 Docker 基础设施，场站环境使用固定版本容器，电力分区边界使用轻量数据代理。各环境共享数据契约、状态语义、版本号和验收测试。

核心链路如下：

```text
SCADA 或 NWP 数据源
        ↓
分区落地目录
        ↓
统一分区代理：校验、编号、可靠落盘、幂等传递
        ↓
统一接入 API：鉴权、校验和验证、接入箱、隔离箱
        ↓
数据适配与数据库
        ↓
预测输入快照、预测、校准、模型审批与回滚
        ↓
可靠上报发件箱：持久化、发送、退避、死信、恢复
        ↓
调度机构或其他业务服务器
```

## 组件职责

| 组件 | 单一职责 | 持久状态 |
| --- | --- | --- |
| 分区代理 | 将稳定文件封装成统一数据包并传递到下一跳 | inbox、processing、processed、quarantine |
| 接入 API | 校验鉴权、契约、大小和 SHA256 | 文件接入箱 |
| 业务接入处理器 | 抢占可靠数据包、适配 NWP、记录批次质量与隔离原因 | ingestion_batches、格点表 |
| 业务后端 | 数据适配、查询、预测和配置 | KingBase |
| SCADA Manager | 独立协调各场站采集 Worker，提供存活与就绪探针 | scada_connections |
| Celery Worker | 预测任务和发件箱发送 | KingBase、Redis |
| Celery Beat | 生成预测计划并常驻触发发件箱恢复 | 调度文件、KingBase |
| 上报发件箱 | 保存待发送载荷和所有发送状态 | report_outbox 表 |
| SCADA 采集与语义映射 | 校验质量、时钟、单位和范围，将五类指标写入规范观测和业务投影 | source_observations、业务表 |
| 预测输入追溯 | 冻结一次运行看到的 SCADA、NWP、模型和数据集版本 | prediction_input_snapshots |
| 运行控制中心 | 汇总输入新鲜度、预测、上报、模型和磁盘健康 | 只读运行快照 |
| 能力事实表 | 告诉前端和运维当前部署真正具备哪些能力 | 部署环境变量、运行健康快照 |

## 关键约束

1. 网络发送前必须先完成本地持久化。
2. 每条跨区消息和上报消息必须具有稳定幂等编号。
3. 处理状态只能沿定义好的状态机变化，失败原因必须可查询。
4. 场站运行不得依赖公网、在线软件仓库或运行时下载。
5. 前端不得把接口异常或数据源缺失展示成正常状态。
6. 发布包必须能追溯到 Git 提交，并通过 SHA256、SBOM 与数字签名策略校验。
7. 场站模式下的新模型默认进入候选状态，审批通过后方可参与预测。
8. 数据保留任务执行归档行数核对，核对成功后才删除在线记录。

## 当前边界

本阶段完成了统一传输底座、可靠上报、五类 SCADA 语义映射、NWP CSV 业务处理、预测输入追溯、模型审批回滚、运行控制中心和带 SBOM 的离线发布校验。极端天气实时检测仍处于占位状态。真实场站点表、NWP 文件格式、网络边界、下游回执和性能指标仍需通过现场 SAT 确认。
