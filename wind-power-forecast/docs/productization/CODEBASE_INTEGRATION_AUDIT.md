## 结论

本分支已经完成商业化基础链路，覆盖五类 SCADA、NWP 业务接入、数据血缘、独立 SCADA Manager、模型治理、运行控制中心、数据归档和离线发布门禁。现有预测算法主体没有调整，训练入口只增加数据集摘要与模型版本注册信息。

当前代码可继续用于工厂验收和场站等价环境联调。修复台账中的 P0 项全部关闭并通过安全回归后，才能形成下一版正式现场发布候选。正式投产还依赖真实点表、真实 NWP、下游服务器、硬件负载和连续运行 SAT。代码库也保留若干历史兼容层和仓库体积问题，适合在基础链路稳定后分批收敛。

## 已完成项

1. 数据库变更通过 Alembic 管理，生产结构检查可设置为严格模式。
2. Flask 不再负责启动 SCADA 采集进程，独立 Manager 统一协调 Worker。
3. SCADA 管理接口支持 JWT 与权限校验，Worker 密钥在场站模式下强制有效，连接目标受网段白名单约束。
4. `scada-point-v2` 统一实发功率、风速、理论功率、可用功率和风机可用率。
5. 有效 SCADA 样本写入规范观测，并更新五类业务投影。
6. NWP 长格式 CSV 进入可靠业务处理器，批次保存摘要、质量、接受数、拒绝数和隔离原因。
7. 每次预测冻结 SCADA、NWP、模型和数据集版本，支持输入追溯。
8. 场站模式关闭模型自动审批，候选模型支持审批、拒绝、摘要校验和回滚。
9. 运行控制中心集中展示数据输入、预测、上报、模型与磁盘健康。
10. 规范观测、接入批次和预测血缘进入先归档后删除的保留策略。
11. 离线发布包含 SHA256、CycloneDX SBOM、固定镜像策略、配置校验和数字签名策略。
12. 独立 FAT 使用真实 `scada_worker.py` 验证五场站五指标，并覆盖 NWP 四类场景。
13. 上报服务器密码、气象连接密码和私钥口令使用独立密钥加密落盘，查询接口仅返回配置状态，历史明文由 Alembic 迁移统一转换；旧部署与诊断入口中的固定数据库和 PgAdmin 密码已经移除。
14. 实际功率采用北京时间十五分钟网格，单条写入、批量导入和 SCADA 投影执行相同校验；评估、训练、校准、功率对比、月度统计、上报取数和实时查看按业务表、规范观测、单机汇总的优先级逐点补源，并保留来源计数。详细契约见 [ACTUAL_POWER_CONTRACT.md](ACTUAL_POWER_CONTRACT.md)。

## P0，现场投产前完成

### 1. 真实数据适配与 SAT

开发适配器已经稳定，真实场站仍需提供正式 C104 点表和 NWP 文件样例。必须核对时间标签、时区、倍率、单位、质量位、网格范围、文件到达周期和补发规则。适配差异通过配置或适配器处理，规范指标和预测输入契约保持稳定。

### 2. 性能容量确认

运行控制中心和 SCADA 健康接口仍会读取多张状态表。五个场站规模已经足够，场站数、测点数或历史数据显著增长时需要基于真实负载检查查询计划、索引命中、磁盘写入和页面响应。

建议在目标硬件执行：

1. SCADA 峰值样本写入与重复投递测试。
2. NWP 多文件并发到达与积压恢复测试。
3. 三种预测尺度并行训练和预测测试。
4. 操作员并发访问和大时间范围查询测试。
5. 数据归档、备份与恢复窗口测试。

### 3. 现场安全审查

当前系统提供共享密钥、JWT、权限、目标网段限制、回环端口和发布签名。现场还需结合安全规范确认主机加固、容器运行权限、日志外送、密钥保管、介质审批、防火墙和漏洞处置流程。需要双向证书时，应在接入代理层增加 mTLS，应用契约无需变化。

### 4. 连续运行与业务签字

至少连续运行七天，覆盖 NWP 更新、模型训练、预测、校准、十五分钟上报、数据归档、数据库备份和一次故障恢复。准确率、出数时限、人工修正和上报合格率由业务负责人签字确认。

## P1，试运行稳定后收敛

### 1. 统一 API 命名空间

项目仍同时保留 `/scada/*`、`/api/*` 和 `/api/v1/*`。新功能已经使用版本化接口，旧接口需要建立调用清单、废弃日期和兼容测试，再按客户端迁移节奏删除。

### 2. 移除 ORM 兼容层

部分模块仍从旧 `models.py` 导入，测试会出现兼容层和 SQLAlchemy 旧接口警告。建议按业务域改为 `db_models`，每批补查询与事务测试，最后删除兼容导出。

### 3. 继续拆分导入副作用

SCADA Manager 已完成拆分。天气调度、部分数据库检查和旧启动入口仍有模块导入副作用。后续将 Web、天气任务、维护任务和一次性初始化拆成独立命令。

### 4. 收敛启动与 Compose 入口

生产以 `deploy/docker-compose.prod.yaml` 为准，本地以 `start-local.bat` 和 `start-scada-dev.bat` 为准。`frontend-backend-compose.yaml` 保留全容器兼容模式，旧 C104 客户端已经放入 `legacy-c104` profile。后续确认没有现场依赖后删除旧入口。

### 5. 完整锁定构建供应链

发布 SBOM 已记录实际预测镜像 Python 包、前端锁文件依赖和镜像摘要。后续还需建立内部 wheelhouse、带哈希的完整 Python 锁文件、基础镜像摘要策略和操作系统包清单，构建机只允许访问内部制品库。

### 6. 控制仓库体积和运行产物

仓库仍包含已跟踪的前端依赖、模型制品、上传样例和 Celery Beat 状态文件。先建立 npm 缓存、Python wheel、模型制品库和测试数据目录，再在独立清理分支移出这些内容。运行状态文件不得继续进入新提交。

### 7. 前端质量门禁与包体积

前端生产构建通过，但 vendor、图表库和视频背景仍产生包体积警告。建议增加 ESLint、组件测试、按页面拆分重型图表依赖，并评估视频背景的延迟加载和低带宽降级。

## 当前验收基线

1. 五个测试场站均能通过真实生产 Worker 上送五类规范指标。
2. 无效质量、异常单位、越界值和时间错误留下审计记录且不更新业务投影。
3. SCADA 断线恢复后健康状态自动恢复。
4. NWP 正常、缺失、非法时间和陈旧场景均有确定结果。
5. 重复消息不产生第二份规范观测、业务批次或上报任务。
6. 每次预测拥有输入快照、不可变输出账本和可核验摘要。
7. 场站模型未经审批不参与预测，制品篡改会阻止审批与回滚。
8. 前端不把未知、缺失、过期或接口异常显示为正常。
9. Windows 批处理保持 UTF-8 与 CRLF，启动失败时保留可读错误。
10. 自动回归、前端构建、Compose 展开、Shell 语法和 FAT 全部通过。
