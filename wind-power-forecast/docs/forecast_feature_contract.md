# 预测特征契约

## 适用范围

本文档约束短期和中期预测服务的训练、模型保存与在线预测。超短期预测拥有独立的逐时移模型和特征生成流程，不复用本文的短期模型接口。

## 当前契约

契约版本为 `short-mid-grid-v1`。

1. 原始 NWP 坐标字段在特征处理中保留坐标后缀，例如 `wind_u_100m_23.8_103.2`。
2. 网格风速和风向采用稳定编号，例如 `ws100_1` 和 `wd100_1`。
3. 网格聚合空气密度采用 `grid_air_density`。
4. 数据按时间顺序切分为 70% 训练集、15% 验证集和 15% 测试集。
5. `train_ensemble` 必须同时接收训练集、验证集、测试集和场站容量。
6. 每次训练必须保存有序且无重复的 `feature_columns`，同时保存契约版本和特征数量。

仓库中的五个场站短期和中期模型均符合该契约。现有模型的 LightGBM、XGBoost、CatBoost 特征数量与对应的 `feature_columns` 一致。

## 在线保护

模型加载时检查特征清单是否存在、是否重复，以及模型内部特征数量是否匹配。在线预测时检查当前特征是否完整覆盖模型训练特征。

任何检查失败都会返回明确的契约错误，预测任务不会继续使用静默填零的输入。这样可以避免 NWP 表结构变化或错误模型包产生表面正常、实际失真的预测结果。

## 历史测试处理

早期测试中的两段数据切分、两参数训练调用、坐标后缀风速字段和 `air_density` 断言已经退出当前短期模型契约。测试现已使用确定性 NWP 样本验证当前字段名称、物理计算结果、三段数据切分、模型训练接口和缺失特征保护。

## 验证命令

在项目根目录执行：

```bash
python -m pytest -q
```

默认测试范围固定为 `backend/tests`，避免一次性诊断脚本和联网测试脚本被误收集。
