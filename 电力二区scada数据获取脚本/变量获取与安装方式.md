1. 服务器连接信息:
SCADA_SERVER_IP:
目的和意义: 这是 SCADA 系统（或其负责 IEC 104 通信的网关/接口机）在网络上的唯一地址。就像你要打电话，必须先知道对方的电话号码一样。你的 Python 脚本（客户端）需要这个 IP 地址才能在网络上找到并尝试连接 SCADA 服务器。
没有它/错了会怎样? 你的脚本根本找不到目标服务器，连接会直接失败（例如 "Connection refused" 或 "No route to host"）。
SCADA_SERVER_PORT:
目的和意义: 一个 IP 地址可以提供多种网络服务（比如网页服务用 80/443 端口，SSH 远程登录用 22 端口）。端口号就是用来区分同一台服务器上不同服务的**“门牌号”。IEC 104 协议有标准的端口号 2404，但为了安全或避免冲突，场站很可能修改了这个端口。你的脚本需要知道确切的端口号，才能连接到 SCADA 服务器上正确**的 IEC 104 服务程序。
没有它/错了会怎样? 即使 IP 地址对了，连接请求也会被发送到错误的“门”（端口），导致连接失败（通常是 "Connection refused"），因为那个端口上可能没有程序在监听，或者监听的是其他服务。
2. IEC 104 协议参数:
CASDU_ADDRESS (ASDU 公共地址):
目的和意义: 在 IEC 104 通信中，即使是点对点连接，通常也需要一个“地址”来标识通信的源和目的站。可以理解为这条通信线路或这个逻辑站点的**“代号”**。SCADA 服务器会检查收到的报文中的这个地址，看是否是发给自己的或者是否来自一个允许的客户端地址。你的脚本在发送请求（如总召唤）或数据时，需要在报文中包含这个地址。有时可能需要配置两个地址（链路地址、站地址）。
没有它/错了会怎样? SCADA 服务器可能会忽略你的请求，或者认为你的请求无效，导致无法建立有效的应用层通信，即使 TCP 连接已经建立。
TIMEOUT_T0 (连接建立超时):
目的和意义: 这是你的客户端尝试与服务器建立 TCP 连接时，愿意等待的最长时间（秒）。
为什么需要问? 网络状况可能不好，服务器可能暂时繁忙。设置一个合理的超时值可以避免在暂时性问题时过早放弃，同时也能防止在服务器确实无法连接时无限期等待。库通常有默认值（比如 5-30 秒），但确认一下场站是否有特定建议（尤其是在网络延迟较大的情况下）是好的。
TIMEOUT_T1 (发送或测试 APDU 的超时):
目的和意义: 当你的客户端发送了一个需要确认的应用层报文（比如一个数据包 I-frame 或一个命令）后，等待对方响应（比如确认 S-frame 或命令执行结果）的最长时间。
为什么需要问? 如果在这个时间内没收到响应，客户端会认为报文丢失或对方无响应，可能会重传或断开连接。这个值需要大于对方处理并响应的时间，但又不能太大导致对真正的问题反应迟钝。库有默认值（比如 15 秒），确认是否有特殊要求。
TIMEOUT_T2 (无数据报文时 S 格式报文的超时):
目的和意义: 当客户端收到数据后，如果暂时没有数据要发回给服务器，它最多等待 T2 秒就必须发送一个确认帧（S-frame），告知服务器已收到数据。T2 必须小于 T1。
为什么需要问? 这个参数确保了即使在通信一方暂时“沉默”的情况下，也能及时确认收到的数据，防止另一方的 T1 超时。库有默认值（比如 10 秒），一般不需要修改，但了解一下没坏处。
TIMEOUT_T3 (长期空闲时发送测试帧的超时):
目的和意义: 当通信链路长时间没有任何数据传输（双向都没有）时，为了防止中间的网络设备（如防火墙）因为“不活跃”而切断连接，双方会定期（每隔 T3 秒）发送一个测试帧（TESTFR）来保持连接“心跳”。
为什么需要问? 如果 T3 设置得太长，防火墙可能已经断开了连接；如果太短，会产生不必要的网络流量。确认一个合适的值（通常比防火墙的空闲超时略短，比如 30-60 秒）可以保持连接稳定。库有默认值。
PARAM_K (发送 K 个 I 格式 APDU 后需等待确认的最大差值):
目的和意义: 发送方在没有收到确认的情况下，最多能连续发送多少个数据帧（I-frame）。这是发送窗口的大小，用于流量控制。
为什么需要问? 双方的 K, W 值必须协调。如果你的 K 值大于服务器的 W 值，你可能会发送过多数据导致服务器处理不过来或丢弃。库有默认值（比如 12），通常双方配置一致即可。
PARAM_W (接收 W 个 I 格式 APDU 后才发送确认):
目的和意义: 接收方最多可以接收多少个数据帧（I-frame）才必须发送一次确认。这是接收窗口的大小。
为什么需要问? 同 K 值，需要与对方协调。库有默认值（比如 8），通常双方配置一致即可。
对于 T0-T3, K, W: 这些参数通常使用库的默认值或标准推荐值就可以工作。但询问场站是否有特定要求或他们系统侧的配置值，可以确保最佳兼容性和稳定性，尤其是在网络环境复杂或对可靠性要求极高的情况下。如果他们没有特定要求，就使用库的默认值。
3. 目标数据点信息:
TARGET_DATA_NAME: "实发功率"
目的和意义: 这是你对所需数据的人类可读描述。主要用于沟通和脚本内的注释，让代码更易懂。这个名字本身不参与 IEC 104 协议交互。
TARGET_IOA (信息体地址):
目的和意义: 极其关键！ 这是 SCADA 系统内部给“实发功率”这个具体数据点分配的唯一数字编号。SCADA 系统里可能有成千上万个数据点（电压、电流、开关位置等），IOA 是区分它们的唯一标识。就像数据库表中的主键 ID。你的脚本在请求数据（总召唤后筛选）或处理接收到的数据时，需要通过这个 IOA 来识别出哪个数值才是你想要的“实发功率”。
没有它/错了会怎样? 你会收到一堆数据但不知道哪个是你想要的，或者你会提取错误数据点的值，导致预测完全错误。必须准确获取！
TARGET_TI (类型标识):
目的和意义: 同样极其关键！ 它定义了与 TARGET_IOA 相关联的数据是以什么格式传输的。比如：
是整数还是带小数的浮点数？(M_ME_NC_1 短浮点数 vs M_ME_NB_1 标度化值)
是否自带时间戳？(M_ME_TF_1 带时标 vs M_ME_NC_1 不带时标)
数值是否经过归一化或标度化处理？
你的 Python 脚本需要知道这个类型，才能正确地解析从网络接收到的原始字节数据，将其转换成有意义的数值和时间戳（如果包含）。
没有它/错了会怎样? 脚本可能会崩溃，或者将收到的字节错误地解析成完全不相关的数值（比如把浮点数按整数解析），导致数据完全错误。必须准确获取！
4. 数据获取方式:
推荐方式:
目的和意义: SCADA 系统可以通过多种方式提供数据（推/拉模式）。了解场站推荐的方式可以让你选择最高效、最可靠、且符合他们系统设计的方法。
总召唤 (C_IC_NA_1): 你主动请求一次，SCADA 把所有（或配置范围内）的数据发给你。适合定时拉取快照。
分组召唤: 只请求特定一组数据。比总召唤更精确。
主动上送 (周期/变化): SCADA 配置为自动把数据“推”给你。你需要保持连接并监听。
为什么需要问? 如果你用拉取的方式去请求一个只配置了推送的系统，可能拿不到数据；反之亦然。遵循推荐方式能避免很多麻烦。
分组召唤 - 组号:
目的和意义: 如果推荐方式是分组召唤，那你必须知道“实发功率”所在的组的编号，才能构造正确的请求报文。
主动上送 - 周期/条件:
目的和意义: 如果是主动上送，你需要了解它是按固定时间间隔（周期）上送，还是仅当数值变化超过一定阈值时才上送。这决定了你的脚本是需要定时触发（如果上送周期比你需要的数据频率慢），还是只需要保持连接并处理收到的数据即可。
5. 网络与安全:
防火墙:
目的和意义: 电力系统的网络通常有严格的安全隔离措施，防火墙是常见的手段。即使你的服务器 B 和 SCADA 在同一个二区，它们之间也可能存在网络防火墙。需要确认从服务器 B 的 IP 到 SCADA 的 SCADA_SERVER_IP 和 SCADA_SERVER_PORT 的 TCP 通信是否被允许。
没确认/没开通会怎样? 你的脚本会无法建立 TCP 连接，现象通常是连接超时 (Timeout)。这是非常常见的部署问题，必须提前确认并请网络管理员开通策略（如果需要）。
特殊认证:
目的和意义: 标准的 IEC 60870-5-104 本身没有复杂的应用层认证机制。但有时可能会通过其他方式增强安全性，例如使用 TLS 加密（虽然不常见于传统电力系统内部），或者有特定的网络准入控制。询问一下可以避免意外的连接障碍。
需要会怎样? 如果有特殊认证而你的脚本没有实现，连接会被拒绝。

严格的虚拟环境隔离:
必须为这个新的 IEC 104 客户端脚本创建一个全新的、独立的 Python 虚拟环境。绝对不要与获取 E 文本的脚本或其他任何应用程序共享虚拟环境，即使它们都用 Python。这可以最大限度地避免库版本冲突。

# 进入你存放 IEC 104 脚本的目录
cd /opt/scripts/iec104_client  # 举例路径
# 创建名为 venv 的虚拟环境
python3 -m venv venv
# 激活虚拟环境 (后续安装库和测试都需要先激活)
source venv/bin/activate
# (在这里安装需要的库，见下一步)
# 使用完毕后退出虚拟环境
# deactivate
Use code with caution.

你的 cron 任务需要确保每次运行时都使用了正确的虚拟环境中的 Python 解释器和库。推荐直接指定虚拟环境中的 Python 路径：
# 示例 Cron 任务 (每 15 分钟执行)
# 使用绝对路径确保 cron 能找到所有东西
0,15,30,45 * * * * /opt/scripts/iec104_client/venv/bin/python /opt/scripts/iec104_client/get_power_data.py >> /var/log/iec104_client.log 2>&1
Use code with caution.
